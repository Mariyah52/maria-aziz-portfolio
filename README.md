# Maria Aziz — Portfolio

A static, multi-page site. No backend, no build step required to run it —
just host the folder as-is (see **Hosting** below).

## Structure

```
index.html            Home
about/index.html      About
work/index.html       Work (filtered project index)
case-study/index.html Case study template — reads ?slug=... from the URL
solutions/index.html  Solutions
research/index.html   Research & Publications
writing/index.html    Writing & Insights
recognition/index.html Recognition & Media
now/index.html        Now
contact/index.html    Contact
assets/               Shared CSS, JS, project data, photo, favicon
build/                Python scripts that generated every page (see below)
```

## Updating a project, or adding a new one

Everything project-related — Home's featured work, the Work page's filtered
grid, and every case study — reads from **`assets/projects-data.js`**. To add
a new project or correct one, edit that one file only; no other page needs
to change, and no rebuild step is required (it's read directly by the
browser at runtime).

Each project is one object in the `PROJECTS` array. Leave any field you
don't have confirmed information for as `null` — the case study page shows
a clearly marked "to be confirmed" placeholder for it rather than inventing
anything. See the comments at the top of the file for the exact field list
and the allowed `status` values (Concept / Prototype / MVP / Pilot / Live /
Research / To be confirmed).

## Updating shared structure (nav, footer, page layout)

The nav, footer, and page shell are generated by `build/generate.py`, and
each page's unique content lives in `build/pages.py`. If you change either
file, regenerate every page with:

```
cd build
python3 pages.py
```

This overwrites every `index.html` in the site with the latest content —
it's the single source of truth for the shared chrome, so you only ever
need to update the nav or footer in one place.

## Hosting

This site uses root-absolute links (`/about/`, `/assets/site.css`, etc.),
so it needs to be served from a domain root — any static host works
(GitHub Pages, Netlify, Vercel, etc.). Opening `index.html` directly from
disk in a browser will work for the home page's own content, but internal
links and the shared CSS/JS won't resolve correctly without a real server
— run a local server (e.g. `python3 -m http.server`) from this folder to
preview it properly before deploying.

The live domain is https://maria-aziz-portfolio.onrender.com, set in
`SITE_URL` (`build/generate.py`) and `SITE_URL_PLACEHOLDER` (`build/pages.py`).
If the domain changes, update both and regenerate.
